本地大模型推理脉络

生成一个 token，要把激活的权重从内存里读一遍，而计算量很小。所以把前沿模型搬出数据中心，难点在内存：放不放得下（容量），读不读得快（带宽）。下面五条技术线和整个商业故事，都在围绕这两个约束。

出发点

解码是在读内存

内存墙（Wulf & McKee, 1995）和 Roofline 模型（Williams & Patterson, 2009）说的是同一件事：算力增长远快于内存带宽。LLM 解码落在带宽受限的那一侧。

每秒 token 上限 ≈ 内存带宽 ÷ 每个 token 要读的字节数
需要的内存 ≈ 总参数 × 每参数比特 ÷ 8（再加 KV cache）
–
权重要占的内存（GB）
–
每个 token 读多少（GB）
–
理论上限（token/s）

理论上限，实际一般只有 50–70%；不含 KV cache，长上下文时还要更多内存。示例参数：DeepSeek-V3 总 671B、激活 37B；gpt-oss-120b 约 117B、激活约 5.1B；Qwen3-30B-A3B 约 30.5B、激活约 3.3B。

MoE 改变了账本

MoE 每个 token 只读几十 B 参数，带宽压力小了；但所有专家都得放在内存里，要几百 GB。问题从"带宽不够"转成了"容量不够"。谁能便宜地提供几百 GB、带宽过得去的内存，谁就能在家跑前沿模型。

线 ①

压缩权重：少读字节

时间工作解决了什么 · 怎么做 · 效果
2016Deep Compression（Han 等，ICLR 最佳论文）关键

问题CNN 几百 MB，放不进片上内存，读外存最耗电

做法剪枝：把绝对值小的权重置零、重训补精度，剩下的存稀疏格式。量化：每层用 k-means 把权重聚成 32–256 簇，只存簇编号，簇中心再微调。霍夫曼编码：编号分布不均匀，再压一层。

效果AlexNet 缩小 35 倍、VGG 49 倍，精度不降。

2016EIE（Han 等，ISCA）

问题压缩后的稀疏模型在通用硬件上跑不快

做法专用芯片直接在压缩格式上算：跳过零权重和零激活，查表解码簇编号。

效果比 GPU 快约 13 倍、能效高三个数量级。

2022LLM.int8()（Dettmers，NeurIPS）

问题大模型（6.7B 以上）直接 8-bit 量化会崩

做法原因是约 0.1% 的隐藏维度有极大的离群激活。把这几列单独用 FP16 算，其余用 INT8 算，再相加。

效果175B 模型显存减半、零精度损失。

2023GPTQ（Alistarh 组，ICLR）

问题4-bit 以下量化掉点太多，逐权重优化又太慢

做法逐层用校准数据算二阶信息，按列量化，每量化一列就把误差分摊到后面的列上补偿。

效果175B 在一张 A100 上 4 小时压到 3–4 bit，困惑度几乎不变。

2023SmoothQuant（Song Han 组，ICML）

问题权重好量化，激活因为离群通道量化不了，W8A8 做不到

做法数学等价变换：激活按通道除以 s，权重乘以 s，把一半的量化难度从激活挪到权重。离线做，推理无开销。

效果530B 模型 W8A8，精度不降，约 1.5 倍加速、显存减半。

2023–24AWQ（Song Han 组，MLSys 2024 最佳论文）关键

问题4-bit 权重量化要在精度和易加速之间二选一

做法只有约 1% 的权重通道重要，重要性看激活幅度。给这些通道乘个缩放再量化，误差变小，全部仍是 INT4。不用反向传播。

效果4-bit 精度接近原模型；成为 vLLM、TensorRT-LLM 的标准方案。

2023QLoRA（Dettmers，NeurIPS）

问题微调大模型需要几百 GB 显存

做法底座用 4-bit NF4（按正态分布分位数取量化点）冻结，只训旁边的 LoRA；量化常数再量化一次；优化器状态可换页到 CPU。

效果一张 48GB 卡微调 65B，效果接近 ChatGPT。

2023–24QuIP#、AQLM（ICML 2024）

问题2-bit 时离群值让量化完全失效

做法QuIP#：先做随机旋转把离群值摊平，再 8 个权重一起用格点码本编码。AQLM：每组权重表示成几个码本向量之和。

效果2-bit 大模型第一次基本可用。

2024–25BitNet b1.58（2024-02）→ 2B4T（2025）

问题事后量化总有损失，能不能一开始就低比特训练

做法训练时权重就限制在 {-1, 0, 1}，用直通估计传梯度；矩阵乘变成加减法。

效果3B 起和 FP16 持平，能耗大降；2B4T 是 4 万亿 token 训的开源版。

2025MXFP4 / NVFP4；gpt-oss 用 MXFP4 发布

问题4-bit 一直是软件技巧，硬件不原生支持

做法每 32（MX）或 16（NV）个元素共享一个缩放，元素是 4-bit 浮点，Tensor Core 直接算。

效果gpt-oss-120b 约 63GB 放进一张 80GB 卡。

2026RFID-MoE 等（ICML 2026）

问题MoE 压缩时所有专家一视同仁，浪费预算

做法按"路由频率 × 有效秩"给专家分配不同的秩，残差用稀疏投影补回。

效果Qwen3-30B 压 60%，困惑度比基线低 8 以上。

走向：事后量化 → 量化感知训练、原生低比特训练 → 硬件原生支持 4-bit 浮点

线 ②

KV cache 与注意力：长上下文的内存大头

时间工作解决了什么 · 怎么做 · 效果
2019MQA（Shazeer）

问题每个头各存一份 K/V，解码时读 KV cache 太慢

做法所有 query 头共享同一个 K 头和 V 头。

效果KV cache 缩小到 1/头数；质量略降。

2022FlashAttention（Dao，NeurIPS）关键

问题注意力要把 N×N 矩阵写回显存再读，长序列显存和时间都爆

做法把 Q、K、V 切块放进片上 SRAM，用在线 softmax 一次算完，从不写回 N×N 矩阵；反向传播重算。结果精确，不是近似。

效果显存从 O(N²) 降到 O(N)，训练约 3 倍快；FA-2、FA-3 继续提速。

2022Orca（OSDI）

问题一批请求要等最长的那个生成完，GPU 大量空转

做法每生成一步就重组一次批：结束的请求立刻走，新请求立刻进。

效果吞吐大幅提升，连续批处理成为标配。

2023vLLM / PagedAttention（SOSP）关键

问题KV cache 要按最大长度预留连续显存，60–80% 浪费掉

做法像操作系统分页一样把 KV 切成固定小块，用块表映射，不需要连续；共享前缀写时复制。

效果浪费降到 4% 以下，吞吐比 HF 高 14–24 倍。

2023GQA（EMNLP）

问题MQA 省内存但掉质量

做法query 头分组，每组共享一对 K/V；已有模型可用 5% 算力升级成 GQA。

效果质量接近多头、速度接近 MQA；Llama 2/3 采用。

2023H2O（NeurIPS）

问题长对话 KV cache 无限增长

做法累计注意力集中在少数 token 上；只保留最近的加累计注意力最高的，其余逐出。

效果留 20% KV 质量几乎不变。

2023 → ICLR 2024StreamingLLM（Song Han 组）

问题滑动窗口一丢掉开头的 token，模型就崩

做法发现"注意力汇点"：开头几个 token 不管内容都吸收大量注意力。永远保留前 4 个 token 的 KV，再加滑动窗口。

效果不微调就能稳定生成 400 万 token。

2024KIVI（ICML）、KVQuant（NeurIPS）

问题KV cache 本身能不能像权重一样量化

做法KIVI：Key 按通道、Value 按 token 量化到 2-bit。KVQuant：Key 在加位置编码前量化，离群值单独存。

效果KV 显存减 2.6 倍；7B 模型单卡支持约 100 万 token。

2024-05MLA（DeepSeek-V2）

问题GQA 还是存了很多 K/V

做法把 K 和 V 联合压成一个低维潜向量（如 512 维）存，用时再投影回去；投影矩阵可合并进 query 侧。

效果KV cache 减少约 93%，效果略好。

2024–25混合注意力：Jamba、MiniMax-01、Qwen3-Next、Kimi Linear

问题只要有标准注意力，KV 就随长度线性增长

做法大部分层换成线性注意力或状态空间（KV 固定大小），只留 1/4 到 1/8 的标准注意力层。

效果Kimi Linear KV 减 75%，百万上下文解码约 6 倍快。

走向：先省带宽（FlashAttention）→ 再省容量（分页、量化、低秩）→ 从模型结构上去掉 KV cache

线 ③

并行解码：读一次权重，多出几个 token

时间工作解决了什么 · 怎么做 · 效果
2022–23投机解码（Leviathan 等 ICML 2023；DeepMind 同期）关键

问题解码每步只出 1 个 token，权重读一次只换来一个 token，算力闲着

做法小模型先猜 γ 个 token，大模型一次前向并行验证；按 min(1, p/q) 接受，拒绝时从修正分布重采样。可证明输出分布和大模型完全一样。

效果2–3 倍加速，零质量损失。

2024Medusa（ICML）

问题找一个合适的草稿小模型很麻烦

做法不要草稿模型，在大模型最后一层加几个预测头，第 k 个头预测后面第 k+1 个 token，候选组成树一次验证。

效果2.2–3.6 倍加速。

2024–25EAGLE → EAGLE-2 → EAGLE-3

问题直接猜 token 不确定性太大，接受率低

做法在特征层（倒数第二层隐藏状态）上预测，并把已采样的 token 喂回去消除不确定性。EAGLE-2 按置信度动态调草稿树；EAGLE-3 融合多层特征。

效果EAGLE 约 3 倍，EAGLE-3 最高约 6.5 倍。

2024-12MTP（DeepSeek-V3）

问题草稿头是事后加的，和主模型不够配合

做法训练时就加一个预测再下一个 token 的模块；推理时直接当草稿用。

效果第二个 token 接受率 85–90%，约 1.8 倍快。

2025扩散语言模型：LLaDA、Mercury、Gemini Diffusion

问题自回归天生是串行的

做法从全掩码序列出发，每步并行预测多个位置，几步揭开整段。

效果LLaDA 8B 和 LLaMA3 8B 相当；Mercury 超过 1000 token/s。

为什么对本地特别重要：本地是单用户、小批量，算力大量闲置。投机解码把闲置的算力换成速度

线 ④

分层存放、按需搬运：容量不够怎么办

时间工作解决了什么 · 怎么做 · 效果
2023FlexGen（ICML）

问题一张小显卡想跑 175B，权重根本放不下

做法把权重、激活、KV 分到 GPU、CPU、磁盘，用线性规划选方案；按之字形调度让一次加载服务多个批次。

效果一张 T4 跑 OPT-175B，约 1 token/s，适合离线批处理。

2023Deja Vu（ICML）

问题每个 token 其实只用到一小部分神经元，却全算了

做法用小预测器提前一层预测哪些注意力头和 MLP 神经元会激活，只算这些。

效果OPT-175B 延迟降 2 倍以上，质量不降。

2023-12 → ACL 2024LLM in a flash（Apple）关键

问题DRAM 只能装下模型的一半，闪存随机读很慢

做法只加载会激活的神经元；保留最近几个 token 用过的，新 token 只读增量；把要一起用的行和列打包存，变成连续读。

效果跑 DRAM 两倍大的模型，GPU 上比朴素加载快 20 倍以上。

2023-12 → SOSP 2024PowerInfer（上交）→ PowerInfer-2（2024）

问题消费级显卡显存小，CPU 内存大但算得慢

做法神经元激活服从幂律：少数热神经元放 GPU，大量冷神经元放 CPU 直接算；在线预测器决定每个 token 用哪些。PowerInfer-2 搬到手机 NPU + 闪存。

效果RTX 4090 跑 OPT-175B 约 13 token/s；手机跑 47B Mixtral。

2023-12Mixtral 卸载（Eliseev & Mazur）

问题MoE 总参数大但每次只用几个专家，显存放不下全部

做法专家在 GPU 上用 LRU 缓存，相邻 token 常复用；用下一层门控提前预取；专家量化到 2–3 bit。

效果T4 显卡上以交互速度跑 Mixtral-8x7B。

2025KTransformers（清华，SOSP）关键

问题671B 的 DeepSeek 在消费级机器上根本跑不起来

做法按结构切：注意力、KV、共享专家放 GPU；路由专家放 CPU 内存用 AMX 指令算；CPU/GPU 异步；Expert Deferral 把部分专家结果推迟一层合并，让两边重叠。

效果一张 16GB 卡 + 大内存跑 671B，提速 1.66–19.7 倍。

2026DALI、FlashMoE、MoE-CORE、FineMoE 等

问题专家放哪、怎么预取、怎么缓存，没有专门的策略

做法按工作负载放置专家；证明 LRU/LFU 不适合专家路由，设计专门的缓存；协调常驻和传输；从闪存直读。

效果2026 最热方向。反面证据：SSD 卸载每 token 能耗可达 HBM 的 12 倍。

走向：通用卸载 → 利用稀疏性 → 针对 MoE 的专家放置、缓存和预取（2026 年最热）。反面证据：用 SSD 卸载 MoE 权重，每 token 能耗可达 HBM 的约 12 倍

线 ⑤

模型结构变得对本地友好

时间工作解决了什么 · 怎么做 · 效果
2023-12Mixtral 8x7B

问题想要 70B 的质量，又只想付 13B 的推理成本

做法每层 8 个专家，每 token 路由到 2 个；总参数 47B，激活 13B。

效果开源 MoE 走进大众。

2024-12 / 2025-01DeepSeek-V3 / R1关键

问题开源模型和前沿闭源模型差距大，训练又太贵

做法671B 总 / 37B 激活：256 个细粒度专家 + 1 个共享专家，每 token 选 8 个；无辅助损失的负载均衡；MLA；MTP；FP8 训练。R1 用强化学习加推理。

效果开源第一次接近前沿；但 4-bit 也要约 340GB，在家跑变成容量问题。

2025Qwen3、Kimi K2（1T）、gpt-oss

问题前沿模型还能不能更稀疏

做法Qwen3 235B/22B 激活和 30B/3B 激活；Kimi K2 1T/32B；gpt-oss 120B/5.1B，直接 MXFP4 发布。

效果总参数越来越大，激活停在几 B 到几十 B。

2025–26Qwen3-Next、Kimi Linear；DeepSeek-V4、Qwen3.5

问题MoE 解决了带宽，KV 和容量还在涨

做法混合线性注意力 + 超稀疏 MoE（如 80B 总 / 3B 激活）。

效果带宽压力继续降，容量压力继续升。

结论：MoE 让瓶颈从带宽转到容量，这是 Alpaca 这类公司成立的时间背景
