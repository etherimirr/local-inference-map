研究与商业脉络 · 2026-11

本地大模型推理脉络

生成一个 token，要把激活的权重从内存里读一遍，而计算量很小。所以把前沿模型搬出数据中心，难点在内存：放不放得下（容量），读不读得快（带宽）。下面五条技术线和整个商业故事，都在围绕这两个约束。

出发点

解码是在读内存

内存墙（Wulf & McKee, 1995）和 Roofline 模型（Williams & Patterson, 2009）说的是同一件事：算力增长远快于内存带宽。LLM 解码落在带宽受限的那一侧。

每秒 token 上限 ≈ 内存带宽 ÷ 每个 token 要读的字节数
需要的内存 ≈ 总参数 × 每参数比特 ÷ 8（再加 KV cache）

理论上限，实际一般只有 50–70%；不含 KV cache，长上下文时还要更多内存。示例参数：DeepSeek-V3 总 671B、激活 37B；gpt-oss-120b 约 117B、激活约 5.1B；Qwen3-30B-A3B 约 30.5B、激活约 3.3B。

MoE 改变了账本

MoE 每个 token 只读几十 B 参数，带宽压力小了；但所有专家都得放在内存里，要几百 GB。问题从"带宽不够"转成了"容量不够"。谁能便宜地提供几百 GB、带宽过得去的内存，谁就能在家跑前沿模型。

线 ①

压缩权重：少读字节

时间工作之前卡在哪 · 做法 · 之后
2016Deep Compression（Han 等，ICLR 最佳论文）关键

之前CNN 的权重用 32-bit 浮点存，AlexNet 240MB、VGG-16 552MB。片上 SRAM 放不下，只能每次从 DRAM 读权重，读 DRAM 的能耗是做一次乘法的几百倍。

做法剪枝：把绝对值小的权重置零、重新训练补回精度，剩下的存成稀疏格式。量化：每层用 k-means 把权重聚成 32–256 簇，每个权重只存簇编号，簇中心再微调。霍夫曼编码：簇编号出现频率不均，再压一层。

之后AlexNet 240MB → 6.9MB（35 倍），VGG 552MB → 11.3MB（49 倍），精度不变，模型能放进片上 SRAM。

2016EIE（Han 等，ISCA）

之前上一条压出来的是稀疏加查表的格式，CPU/GPU 不会直接算，要先解压回稠密矩阵，省下的内存和能耗又还回去了。

做法设计一块专用芯片，直接在压缩格式上算：跳过为零的权重和激活，用查表把簇编号还原成权重值，多个处理单元并行处理不同的行。

之后全连接层上比 GPU 快约 13 倍、能效高约 3,400 倍。结论：压缩要配专用硬件才能兑现。

2022LLM.int8()（Dettmers 等，NeurIPS）

之前大模型用 FP16 存和算，每个参数 16 bit，175B 要 350GB 显存。想改成 INT8（8 bit）把显存减半：小模型可以，但 6.7B 以上一改精度就崩。原因是约 0.1% 的隐藏维度会出现幅度极大的离群值，按 8 bit 量化时这些极大值把其余正常数值全压成 0。

做法混合精度分解：把含离群值的那几列单独挑出来，仍用 FP16 相乘；其余 99.9% 的列用 INT8 相乘；两部分结果相加。

之后175B 可以用 INT8 存和算，显存从 350GB 降到 175GB，精度和 FP16 完全一样；集成进 Hugging Face，一行参数启用。

2023GPTQ（Alistarh 组，ICLR）

之前INT8 已经可用，但还想更小。降到 4 bit 以下，简单四舍五入掉点严重；逐个权重做最优补偿（OBQ）精度好，但 1B 以上的模型算不动。

做法逐层做，用少量校准数据算出该层输入的二阶信息。按列依次量化，每量化完一列就把产生的误差分摊到还没量化的列上去补偿；批量更新和 Cholesky 分解让它在大模型上跑得动。

之后175B 在一张 A100 上约 4 小时量化到 3–4 bit，困惑度几乎不变；3-bit 的 175B 能放进单张 80GB 显卡。

2023SmoothQuant（Song Han 组，ICML）

之前权重量化到 INT8 没问题，但要用 GPU 的 INT8 算子真正加速，激活也得是 INT8。激活里有些通道的数值比别的大上百倍，INT8 一量化，小数值全变 0，所以 W8A8（权重和激活都 8 bit）一直做不到。

做法一层的计算是 Y = X·W（X 是激活，W 是权重）。X 的第 j 个通道如果有离群值，就给这一通道除以一个系数 s_j，同时把 W 的第 j 行乘以同一个 s_j；因为 (X_j / s_j)·(s_j·W_j) = X_j·W_j，结果一个数都不变。为什么有用：量化误差由每个张量里的最大值决定（最大值定了刻度，小数被压扁）。除以 s_j 后激活这一通道的最大值降下来了；权重那一行虽然被放大，但权重本来分布平坦、没有离群值，放大一点仍然好量化。s_j 怎么取：s_j = max|X_j|^α ÷ max|W_j|^(1−α)，α 取 0.5 时两边的最大值被拉到同一量级。比如某通道激活最大 100、权重最大 1，s = 10，之后激活最大 10、权重最大 10，都能用 INT8 表示。系数用校准数据离线算好，直接乘进权重里存起来，推理时没有额外计算。

之后530B 模型做到 W8A8，精度不降，用上 INT8 Tensor Core：约 1.56 倍加速、显存减半。

2023–24AWQ（Song Han 组，MLSys 2024 最佳论文）关键

之前4-bit 权重量化成了主流需求。GPTQ 靠校准数据做优化，容易对校准集过拟合、换任务掉点；把重要权重保留成 FP16 精度好，但变成混合精度，硬件不好加速。

做法发现只有约 1% 的权重通道重要，而且重要性要看对应激活的幅度，不是权重本身。给这些通道乘一个大于 1 的系数再量化，它们的相对误差就变小；系数用激活统计做小范围搜索。全部权重还是统一的 INT4，不用反向传播。

之后4-bit 精度接近原模型，跨任务稳定；配 TinyChat 在桌面 GPU 和 Jetson Orin 上约 3 倍快。成了 vLLM、TensorRT-LLM、Hugging Face 的标准 4-bit 方案。

2023QLoRA（Dettmers 等，NeurIPS）

之前微调 65B 模型要存 16-bit 权重、梯度和优化器状态，需要 780GB 以上显存，只有大集群做得了。

做法底座模型用 4-bit NF4 存（量化点按正态分布的分位数取，因为预训练权重近似正态）并冻结，只训练插在旁边的 LoRA 低秩适配器；量化常数本身再量化一次；优化器状态在显存不够时换页到 CPU 内存。

之后一张 48GB 显卡就能微调 65B，效果达到 ChatGPT 约 99%。消费级显卡能微调大模型。

2023–24QuIP#（ICML 2024）、AQLM（ICML 2024）

之前4-bit 已经成熟。再往下到 2-bit，每个权重只有 4 个取值，离群值一出现，均匀量化的误差大到模型不可用。

做法QuIP#：先给权重矩阵前后乘随机 Hadamard 旋转，把离群值"摊平"成均匀分布，再 8 个权重一组用格点码本编码。AQLM：每组权重表示成几个码本向量之和，码本和编码联合优化。

之后2-bit 的大模型第一次基本可用，在 2-bit 区间达到当时最好的精度和体积折中。

2024–25BitNet b1.58（2024-02）→ BitNet 2B4T（2025-04）

之前以上都是训练完再量化，总会有损失；而且就算权重是 4 bit，算的时候还是乘法。

做法从训练开始就把权重限制在 {-1, 0, 1} 三个值（除以平均绝对值后四舍五入），激活用 8 bit，训练时用直通估计让梯度穿过取整。矩阵乘法变成只有加减法。

之后3B 规模起和同大小的 FP16 模型持平，延迟、显存、能耗大幅下降；2B4T 是用 4 万亿 token 训的开源版，配 bitnet.cpp 在 CPU 上跑。

2025MXFP4 / NVFP4；gpt-oss 以 MXFP4 发布（2025-08）

之前4-bit 一直是软件层面的技巧：GPU 的 Tensor Core 不原生算 4 bit，推理时要先解压回 16 bit 再乘，省了显存没省算力。

做法MXFP4（OCP 标准）：每 32 个元素共享一个 8-bit 缩放，元素是 4-bit 浮点。NVFP4（Blackwell）：每 16 个共享一个 FP8 缩放，再加张量级缩放。两种格式 Tensor Core 直接计算。

之后4-bit 浮点进了硬件和官方发布的模型：gpt-oss-120b 约 63GB 放进单张 80GB 卡，20b 放进 16GB。

2026RFID-MoE 等 MoE 专家级压缩（ICML 2026）

之前对 MoE 做 SVD 低秩压缩时，所有专家分到同样的秩，但有的专家几乎每个 token 都用、有的很少用。

做法按"路由频率 × 有效秩"给每个专家打分，重要的专家组分到更多秩；压缩丢掉的残差再用参数很少的稀疏投影补回一部分。

之后Qwen3-30B 压缩 60% 时，困惑度比之前的方法低 8 以上。

走向：事后量化 → 量化感知训练、原生低比特训练 → 硬件原生支持 4-bit 浮点

线 ②

KV cache 与注意力：长上下文的内存大头

时间工作之前卡在哪 · 做法 · 之后
2019MQA（Shazeer）

之前解码每出一个 token，都要把之前所有 token 的 K 和 V（KV cache）读一遍，每个注意力头各存一份；32–96 个头时，长序列的 KV cache 比模型权重还大，解码时间主要花在读它。

做法所有 query 头共享同一个 K 头和 V 头。

之后KV cache 缩小到原来的 1/头数，解码读内存大减；质量略有下降。PaLM、Falcon 采用。

2022FlashAttention（Dao 等，NeurIPS）关键

之前标准注意力要把 N×N 的分数矩阵完整写进显存，再读回来做 softmax，显存 O(N²)；序列到几千就放不下，而且时间主要耗在读写显存上，不是计算。

做法把 Q、K、V 切成小块装进片上 SRAM，用"在线 softmax"边算边维护最大值和归一化分母，一次算完，从不把 N×N 矩阵写回显存；反向传播时重算而不存。结果和标准注意力完全一样。

之后显存从 O(N²) 降到 O(N)，GPT-2 训练约 3 倍快，上万 token 的上下文变得可行。FA-2（2023）再快约 2 倍，FA-3（2024）用上 Hopper 的 FP8。

2022Orca（OSDI）

之前推理服务按批处理：一批请求要等最长的那个生成完才能换下一批，短的先结束了，它的位置就空着。

做法迭代级调度：每生成一步就重组一次批，结束的请求立刻离开、新请求立刻加入。

之后同等延迟下吞吐最高约 37 倍。连续批处理成为所有推理服务的标配。

2023vLLM / PagedAttention（Kwon 等，SOSP）关键

之前每个请求的 KV cache 要预先占一整段连续显存，按最大长度留，实际大多用不到，60–80% 的显存浪费掉，一批塞不下几个请求。

做法像操作系统虚拟内存一样把 KV cache 切成固定大小的块（如 16 个 token 一块），用块表把逻辑位置映射到物理块，不需要连续；多个请求共享前缀时写时复制。

之后浪费降到 4% 以下，一批能放更多请求，吞吐比 Hugging Face 高 14–24 倍。

2023GQA（Ainslie 等，EMNLP）

之前MQA 省内存但质量掉；多头质量好但 KV 大。

做法query 头分成 G 组，每组共享一对 K/V；已训好的多头模型用原训练约 5% 的算力就能改成 GQA。

之后质量接近多头、速度接近 MQA。Llama 2 70B、Llama 3、Mistral 都用它。

2023H2O（NeurIPS）

之前多轮对话里 KV cache 随长度无限增长，最终显存放不下。

做法累计注意力集中在少数"重击者"token 上。只保留最近的 token 加累计注意力最高的 token，其余逐出。

之后只留 20% 的 KV，质量接近完整版。

2023 → ICLR 2024StreamingLLM（Song Han 组）

之前想用滑动窗口只留最近 token 的 KV，但一丢掉开头那几个 token，模型立刻崩，困惑度飙升。

做法发现注意力汇点：开头几个 token 不管内容是什么都吸收大量注意力，因为 softmax 总要把多余的注意力放到某处。永远保留最前面 4 个 token 的 KV，再加滑动窗口。

之后不微调、不重算，就能稳定生成 400 万 token 以上。

2024KIVI（ICML）、KVQuant（NeurIPS）

之前权重已经压到 4 bit，KV cache 还是 16 bit；长上下文时 KV 反而成了显存大头。

做法KIVI：Key 有离群通道所以按通道量化，Value 按 token 量化，2 bit，不用调参。KVQuant：Key 在加旋转位置编码之前量化，用非均匀量化点，少量离群值单独存。

之后KV 显存减少约 2.6 倍、吞吐提升 2.4–3.5 倍；7B 模型在一张 A100 上支持约 100 万 token 上下文。

2024-05MLA（DeepSeek-V2）

之前GQA 之后每层还是要存好几组完整的 K 和 V。

做法把每个 token 的 K 和 V 联合压成一个低维潜向量（如 512 维）存进缓存，算注意力时再投影回去；投影矩阵可以并进 query 侧，不用真的展开。

之后KV cache 比标准多头注意力减少约 93%，效果还略好。

2024–25混合注意力：Jamba、MiniMax-01、Qwen3-Next、Kimi Linear

之前只要用标准注意力，KV 就随长度线性增长，百万 token 时 KV 要几十 GB。

做法大部分层换成 KV 固定大小的层（线性注意力、状态空间），只留 1/4 到 1/8 的标准注意力层。Jamba 是 Transformer 和 Mamba 1:7；Qwen3-Next 是 DeltaNet 和门控注意力 3:1，再加 80B 总 / 3B 激活的超稀疏 MoE。

之后Kimi Linear 报告 KV 减少 75%、百万上下文解码约 6 倍快；MiniMax-01 支持约 400 万 token。

走向：先省带宽（FlashAttention）→ 再省容量（分页、量化、低秩）→ 从模型结构上去掉 KV cache

线 ③

并行解码：读一次权重，多出几个 token

时间工作之前卡在哪 · 做法 · 之后
2022–23投机解码（Leviathan 等 ICML 2023；DeepMind 同期）关键

之前自回归每一步都要把全部权重读一遍，却只产出 1 个 token。内存带宽占满了，算力只用了一小部分，本地单用户时尤其浪费。

做法小草稿模型先连续猜 γ 个 token，大模型一次前向并行算出这 γ+1 个位置的概率。逐个检查草稿：以 min(1, p/q) 的概率接受；一旦拒绝就从修正分布重新采样并停止。可以证明输出分布和大模型自己生成完全相同。

之后读一次权重能出 2–4 个 token，2–3 倍加速，质量零损失。

2024Medusa（ICML）

之前投机解码需要一个和大模型分布接近的小草稿模型，很多模型家族没有现成的。

做法不要草稿模型，在大模型最后一层加几个额外的预测头，第 k 个头预测后面第 k+1 个 token；多个头的候选组成一棵树，用树形注意力一次验证。

之后2.2–3.6 倍加速，只需训练新加的头。

2024–25EAGLE → EAGLE-2 → EAGLE-3

之前Medusa 直接从隐藏状态猜 token，后面几个 token 的接受率低。

做法EAGLE：在特征层（倒数第二层隐藏状态）上自回归预测，比猜 token 容易，并把已采样的 token 喂回去消除不确定性；草稿头只有一层。EAGLE-2：按草稿置信度动态调整草稿树形状。EAGLE-3：融合多层特征，训练时模拟多步草稿。

之后EAGLE 约 3 倍加速，EAGLE-3 最高约 6.5 倍。

2024-12MTP（DeepSeek-V3）

之前草稿头都是训好模型后再加的，和主模型配合有限。

做法预训练时就加一个预测"再下一个 token"的模块，训练信号更密；推理时这个模块直接当投机解码的草稿。

之后第二个 token 接受率 85–90%，生成约 1.8 倍快。

2025扩散语言模型：LLaDA、Mercury、Gemini Diffusion

之前上面所有方法都还在自回归框架里，本质仍是从左到右串行。

做法从一整段全是掩码的序列出发，每一步并行预测多个位置，几步就揭开整段。LLaDA 是 8B 掩码扩散模型从头训练；Mercury 是商用代码模型。

之后LLaDA 8B 和 LLaMA3 8B 相当；Mercury 在 H100 上超过 1000 token/s。

为什么对本地特别重要：本地是单用户、小批量，算力大量闲置。投机解码把闲置的算力换成速度

线 ④

分层存放、按需搬运：容量不够怎么办

时间工作之前卡在哪 · 做法 · 之后
2023FlexGen（ICML）

之前GPU 显存放不下模型就跑不了，只能上多卡。

做法把权重、激活、KV cache 分配到 GPU、CPU、磁盘三层，用线性规划选最优方案；按"之"字形顺序调度，让一次加载的权重服务多个批次；权重和 KV 再压到 4 bit。

之后一张 16GB 的 T4 能跑 OPT-175B，约 1 token/s。只适合离线批处理，不适合对话。

2023Deja Vu（ICML）

之前每个 token 都把全部参数算一遍，但实际每个输入只用到一小部分注意力头和 MLP 神经元。

做法用小的预测器提前一层预测这一层会用哪些头和神经元（和上一层的计算并行），只算这些。

之后OPT-175B 推理延迟降低 2 倍以上，质量不降。

2023-12 → ACL 2024LLM in a flash（Apple）关键

之前手机和笔记本的 DRAM 小，模型放不下；闪存够大，但带宽只有 DRAM 的几十分之一，随机小块读尤其慢。朴素地按需从闪存读，每个 token 要几秒。

做法只加载会激活的神经元：用 ReLU 的稀疏性和低秩预测器预测哪些行要用。窗口化：保留最近几个 token 用过的神经元，新 token 只读新增部分。行列打包：把一起使用的上投影列和下投影行存在一起，变成一次大块的连续读。

之后能跑 DRAM 两倍大的模型；比朴素加载，CPU 上快 4–5 倍、GPU 上快 20–25 倍。

2023-12 → SOSP 2024PowerInfer（上交 IPADS）→ PowerInfer-2（2024-06）

之前消费级显卡 24GB 显存跑不了 175B；全放 CPU 内存又太慢。

做法发现神经元激活服从幂律：少数热神经元几乎对所有输入都激活，大量冷神经元偶尔激活。离线画像后热神经元放 GPU，冷神经元放 CPU 并直接在 CPU 上算；在线预测器决定每个 token 用哪些。PowerInfer-2 把它搬到手机：NPU + CPU 协同，和闪存读取流水线化。

之后一张 RTX 4090 跑 OPT-175B 约 13 token/s，比 llama.cpp 快最高 11 倍；手机上能跑 47B 的 Mixtral。

2023-12Mixtral 卸载（Eliseev & Mazur）

之前Mixtral 47B 总参数放不进 16GB 的 T4，但每个 token 只用 8 个专家里的 2 个。

做法专家在 GPU 上用 LRU 缓存，相邻 token 常复用同一批专家；用下一层的门控提前猜要用的专家并预取；注意力 4 bit、专家 2–3 bit。

之后T4 或 RTX 3060 上以每秒几个 token 的交互速度跑 Mixtral-8x7B。

2025KTransformers（清华 MADSys，SOSP）关键

之前DeepSeek 671B 在消费级机器上根本跑不起来；之前的卸载方案没有针对 MoE 结构，CPU 和 GPU 互相等。

做法按 MoE 结构切分：注意力、KV cache、共享专家放 GPU；256 个路由专家放 CPU 内存，用 AMX 指令优化的 CPU 核计算；CPU/GPU 异步调度；Expert Deferral 把部分专家的结果推迟到下一层再合并，让两边的计算重叠。

之后一张 16GB 消费级显卡加大内存就能跑 671B，吞吐提升 1.66–19.7 倍；2026 年已扩展到 FP8 跑 DeepSeek-V3、Qwen3.5-397B。

2026DALI、FlashMoE、MoE-CORE、FineMoE（EuroSys '26）等

之前KTransformers 把专家放 CPU 内存，但更大的 MoE 连内存也放不下；专家在 GPU、内存、闪存之间怎么放、怎么预取、怎么缓存，还没有专门的策略。

做法DALI 按工作负载在本地 PC 的 CPU/GPU 间放专家；FlashMoE 从闪存直读专家，并证明 LRU/LFU 这类通用缓存策略不适合专家路由；MoE-CORE 协调专家常驻和传输；FineMoE 做细粒度卸载。

之后这是 2026 年本地 MoE 推理最热的方向。反面证据：用现有 SSD 卸载 MoE 权重，每个 token 的能耗可达 HBM 的约 12 倍。

走向：通用卸载 → 利用稀疏性 → 针对 MoE 的专家放置、缓存和预取（2026 年最热）。反面证据：用 SSD 卸载 MoE 权重，每 token 能耗可达 HBM 的约 12 倍

线 ⑤

模型结构变得对本地友好

时间工作之前卡在哪 · 做法 · 之后
2023-12Mixtral 8x7B（Mistral）

之前想要更强的模型就得更大的稠密模型，每个 token 要读的参数和推理成本一起线性上涨。

做法每层 8 个专家，每个 token 由路由器选 2 个；总参数约 47B，每 token 只激活约 13B。

之后质量接近 70B 稠密模型、速度接近 13B；开源 MoE 走进大众。

2024-12 / 2025-01DeepSeek-V3 / R1关键

之前开源模型（如 Llama 3 405B 稠密）和闭源前沿差距大，训练成本又极高。

做法671B 总参数、每 token 激活 37B：256 个细粒度路由专家加 1 个共享专家，每 token 选 8 个；无辅助损失的负载均衡；MLA 压 KV；MTP；FP8 混合精度训练。R1 在 V3 上用强化学习训练推理。

之后开源模型第一次接近前沿，训练约 560 万美元 GPU 时。代价：4 bit 也要约 340GB，在家跑从带宽问题变成容量问题。

2025Qwen3（04）、Kimi K2（07）、gpt-oss（08）

之前DeepSeek 证明了细粒度 MoE 可行，大家跟进。

做法Qwen3：235B 总 / 22B 激活，另有 30B / 3B 激活的小版本。Kimi K2：1T 总 / 32B 激活。gpt-oss：120B / 5.1B 激活和 20B / 3.6B 激活，权重直接以 MXFP4 发布，Apache 2.0。

之后前沿开源模型几乎全是 MoE：总参数越来越大，激活停在几 B 到几十 B。

2025–26Qwen3-Next、Kimi Linear；DeepSeek-V4、Qwen3.5

之前MoE 解决了带宽压力，但 KV cache 和总容量还在涨。

做法混合线性注意力加超稀疏 MoE（如 80B 总 / 3B 激活）。

之后带宽压力继续下降，容量压力继续上升。

结论：MoE 让瓶颈从带宽转到容量，这是 Alpaca 这类公司成立的时间背景
